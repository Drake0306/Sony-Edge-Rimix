# Open-source repositories for Sony Alpha / FX / ZV / RX remote control, live view, wireless connection and image transfer (catalogue as of 2026-11-10)

Method note: candidate repos were collected with ~45 GitHub repository searches (`gh api search/repositories`, sorted by stars) plus GitLab project search; Codeberg's search API returned non-JSON and was not usable. For every repo in the table, stars, license, default-branch last-commit date, `pushed_at`, latest release and README were fetched from the GitHub REST API on **2026-11-10**. "Last commit" = newest commit on the default branch; where `pushed_at` is much newer than that (e.g. alpha-fairy) the pushes went to non-default branches. Star counts are small for most 2025-2026 projects because they are weeks or months old.

Status legend: **Alive** = commits in the last 6 months; **Stalled** = 6-24 months idle; **Dead** = >24 months idle or archived.

## Key Question 0: What exists? (comparison catalogue)

### Takeaway
About 60 relevant repos exist; roughly 20 are directly relevant to a desktop app that controls a Sony body wirelessly. They split into four protocol families: (1) the legacy JSON-RPC "Camera Remote API"/ScalarWebAPI used by pre-2020 bodies (large, mostly dead ecosystem), (2) direct, reverse-engineered PTP/IP with Sony's SDIO vendor extensions on 2020+ bodies (small but very active 2025-2026 wave: alpha2go, sarnau, alphawire, SonyCamViewer, remote-camera-control-rs), (3) wrappers over Sony's proprietary Camera Remote SDK (CrSDK), which officially supports Wi-Fi with Access Authentication (RemoteCam, alpha-sdk-api, CrSDKPy, sony-crsdk-rust, ONAIR, TetherMoon), and (4) BLE remote/geotag projects (alpharemote, freemote, furble, AlphaPro, alfa). Image-transfer-only tools form a fifth group (sony-pm-alt lineage via PTP/IP "Send to Computer", and ImagingEdge4Linux lineage via the SOAP "Send to Smartphone" service).

## Key Question 1: Which repos are the best starting points or references for a desktop wireless Sony controller, and why?

### Takeaway
For a macOS + Windows app that connects over Wi-Fi to 2020+ bodies there are two viable architectures with living exemplars: wrap Sony's CrSDK (RemoteCam is the only complete, cross-platform, MIT, actively released desktop app doing exactly the user's goal) or speak PTP/IP directly (alpha2go has the most complete documented vendor-op coverage incl. SSH Access Authentication; sarnau documents the BLE→Wi-Fi handoff that makes "QR/no-IP-entry" onboarding possible; SonyCamViewer proves a Kotlin Mac+Android direct-PTP3 app). rocc and its Rust port are the best architecture references for routing legacy vs. modern bodies.

### Cited Findings
- RemoteCam ships Windows installer, Apple Silicon and Intel DMGs, connects over Wi-Fi with the camera's Access Authentication user/password, reconnects by itself, and lists the Sony Wi-Fi-remote-capable bodies; MIT; v1.0.13 released 2026-11-05 — [RemoteCam README](https://github.com/RemingtonWilcox/RemoteCam)
- RemoteCam's repo contains a native C++ `CamBridge` CMake target and 11 code hits for "CrSDK", i.e. it is a CrSDK wrapper, and the SDK itself is not redistributed in source — [RemoteCam tree/code search](https://github.com/RemingtonWilcox/RemoteCam/tree/main/native)
- alpha2go implements PTP/IP + Sony vendor ops in pure Go with no SDK/cgo, including SSH-tunnel Access Authentication with fingerprint check, WoL, live view with metadata/OSD, card listing/resumable download, settings backup/restore and LUT import; tested on α6700 fw 2.00 — [alpha2go](https://github.com/Knallli/alpha2go); setup/auth details in [docs/camera-setup.md](https://github.com/Knallli/alpha2go/blob/main/docs/camera-setup.md)
- sarnau's client goes BLE scan → write `01` to `0000CC08` → read SSID/password from `0000CC06/0000CC07` → join AP → TCP 15740 → SDIO_Connect → shoot/download, "No IP address or manual setup needed", verified on A7R V — [sony-camera-protocol](https://github.com/sarnau/sony-camera-protocol)
- alphawire is a C library with Windows/macOS/Linux USB backends plus a TCP/IP backend, ImGui debug GUI, and explicitly supports pre- and post-2020 Alpha bodies; limitation "PTPIP backend doesnt support SSL" — [alphawire](https://github.com/watsonmw/alphawire)
- SonyCamViewer (Kotlin, Mac + Android) connects over USB-C or Wi-Fi (router or Wi-Fi Direct) to any PC-Remote-capable body with no drivers or third-party libraries and expects 2020+ bodies to work because they share the ZV-E10's protocol version — [SonyCamViewer README.en](https://github.com/Scryptor/SonyCamViewer/blob/main/README.en.md)
- rocc (Swift) routes between "API driven (e.g. a7ii)" and "PTP/IP model (e.g. a9ii)" bodies with SSDP discovery that restarts on Wi-Fi changes, but its last default-branch commit is 2021-05-19 — [rocc](https://github.com/simonmitchell/rocc); remote-camera-control-rs is a Rust port with the same three-backend model (ScalarWebAPI / DigitalImaging / PTP/IP), a6700 PTP/IP writes verified, last commit 2026-04-12 — [remote-camera-control-rs](https://github.com/Streetblock/remote-camera-control-rs)
- Sony's CrSDK gained Wi-Fi connectivity in version 1.12 — [tkt1957 summary of Sony SDK 1.12](https://tkt1957.com/sony-camera-remote-sdk-1-12/); the SDK's `CrAdapter` folder contains `Cr_PTP_IP`, `Cr_PTP_USB` and `libssh2` binaries — [CrSDK.IP directory listing](https://github.com/sohtamei/CrSDK.IP)
- Projects wrapping CrSDK all state the SDK cannot be redistributed and must be downloaded by the user (RemoteCam shows a Sony-terms dialog; ONAIR, TetherMoon, CrSDKPy, alpha-sdk-api, sony-crsdk-rust, alphalink say so explicitly) — [ONAIR](https://github.com/jambyylf/onair-camera-control), [TetherMoon](https://github.com/SpaceDLFactory/TetherMoon), [CrSDKPy](https://github.com/PICKLERICK2005/CrSDKPy), [alphalink](https://github.com/nulltrope/alphalink)
- For the image-transfer side, dykomenko/camera-wifi-transfer handles PTP/IP "Send to Computer" discovery on the real LAN adapter, manual IP, `.part` atomic downloads and USB `PMHOME` pairing — [camera-wifi-transfer](https://github.com/dykomenko/camera-wifi-transfer); ImagingEdge-Next adds QR-code scanning to join the camera AP for the SOAP "Send to Smartphone" path — [ImagingEdge-Next](https://github.com/kalicyh/ImagingEdge-Next)

### Inferences
- **Fork candidates:** RemoteCam (closest to the goal, MIT, Win+Mac, actively released) if the user accepts a CrSDK dependency and Sony's EULA for binaries; alpha2go/alpha2web (Apache-2.0) if the user wants SDK-free PTP/IP and is willing to port Go to their stack or embed a Go core.
- **Study for protocol:** sarnau/sony-camera-protocol (BLE→Wi-Fi handoff, vendor op numbers, throughput figures), alpha2go docs/protocol.md and docs/properties.md, alphawire (C backends, Windows WIA/libusbk tricks), SonyCamViewer docs/protocol.md (PTP3 labels, pre-2020 step-based exposure writes), RobertDamerius PTPIP.md (minimal FX3 example), peiyuanix patcher (what Creators' App actually does on connect).
- **Architecture reference:** rocc / remote-camera-control-rs for supporting both legacy (JSON API) and modern (PTP/IP) bodies behind one interface.
- **Reference only / dead:** pysony, libsonyapi, kz-remote-api/locana, timelapse-sony, SonyAlphaUSB, alphamote, Brqtt, sony-pm-alt.
- A desktop "QR scan" onboarding like Creators' App is not implemented by any desktop repo found; ImagingEdge-Next does QR on mobile only, and sarnau/AlphaPro show the alternative of pulling SSID/password over BLE, which a Mac/Windows app with Bluetooth could reuse.

### Gaps
- No repo found implements Sony's non-SSH "pairing" PTP/IP mode on 2020+ bodies with Access Authentication turned off; alpha2go says that path "has not been tested".
- Whether CrSDK's Wi-Fi mode supports the camera-as-access-point (Wi-Fi Direct) topology vs. infrastructure only was not established from these repos (RemoteCam and ONAIR both require camera and PC on the same router Wi-Fi).

## Key Question 2: Which repos have actually solved Wi-Fi connection to 2020+ Sony bodies?

### Takeaway
Confirmed, hardware-tested wireless control of 2020+ bodies exists in two forms: SDK-free PTP/IP (alpha2go on α6700; sarnau on A7R V; jakkuh on FX30/A6700; RobertDamerius on FX3 fw 7.00; remote-camera-control-rs on α6700; SonyCamViewer on ZV-E10; alpha-fairy on A1/A6600) and CrSDK-over-Wi-Fi (RemoteCam on A7S III fw 5.01; ONAIR on FX30; sony-crsdk-rust via IP+SSH credentials). All SDK-free modern paths that handle Access Authentication do it through an SSH tunnel to the camera.

### Cited Findings
- alpha2go: "Everything below was tested on a Sony α6700 (ILCE-6700, firmware 2.00)"; with Access Authentication on, "the camera only accepts connections through its SSH server"; without it the camera "opens plain PTP/IP on port 15740 and asks for pairing on the first connection. This path has not been tested." — [alpha2go camera-setup](https://github.com/Knallli/alpha2go/blob/main/docs/camera-setup.md)
- jakkuh/sony-alpha-python: uses "the SSH authentication method, not the pairing method as SSH tunneling was far more reliable"; requires "a camera compatible with Sony's PTP 3 protocol (FX30, A6700 are examples)" with "Remote Shoot Function" enabled — [sony-alpha-python](https://github.com/jakkuh/sony-alpha-python)
- sarnau: end-to-end against ILCE-7RM5 fw 310: shutter, AF, 60 MP download ~12 MB/s, live view 25.7 fps at 640x424 or 1024x680, 446 properties decoded, 190 writable — [sony-camera-protocol](https://github.com/sarnau/sony-camera-protocol)
- RobertDamerius: PTP/IP without Sony SDK, tested on ILME-FX3 fw v7.00 (connect, set shutter/F/ISO, live view, capture, fetch) — [SonyRemoteCameraControl](https://github.com/RobertDamerius/SonyRemoteCameraControl)
- remote-camera-control-rs: α6700 "controlled through PTP/IP", confirmed writes for ISO, aperture, shutter, EV, WB — [remote-camera-control-rs](https://github.com/Streetblock/remote-camera-control-rs)
- SonyCamViewer: built on ZV-E10 fw 2.00 over USB-C or Wi-Fi; 2020+ bodies "most likely everything: they use the same protocol version"; pre-2020 bodies change exposure in ±1 steps so direct writes "most likely won't work" — [SonyCamViewer README.en](https://github.com/Scryptor/SonyCamViewer/blob/main/README.en.md)
- alpha-fairy: PTP/IP reverse-engineered by sniffing Imaging Edge Remote; supported A1, A6600, A6000, RX100M4, RX0M2; open issue "Almost immediate disconnect from Sony A7Cii" (#39, 2024-09) and README "The camera does not re-establish a broken connection" — [alpha-fairy](https://github.com/frank26080115/alpha-fairy), [issue #39](https://github.com/frank26080115/alpha-fairy/issues/39)
- RemoteCam: Wi-Fi, "Tested on the Sony A7S III" fw 5.01; requires camera on the same Wi-Fi, Remote Shooting On, Access Authen. user/password; "Won't work over Wi-Fi: A7R IV, A7R IVA, A7C, RX0 II" — [RemoteCam README](https://github.com/RemingtonWilcox/RemoteCam)
- ONAIR: "Control up to 3 Sony cameras (tested: FX30) over Wi-Fi" via CrSDK v2.02.00 on Windows — [onair-camera-control](https://github.com/jambyylf/onair-camera-control)
- sony-crsdk-rust: connects with `--ip`, `--mac`, `SONY_SSH_USER`, `SONY_SSH_PASSWORD` (network) or USB on macOS/Linux — [sony-crsdk-rust](https://github.com/luizribeiro/sony-crsdk-rust)
- danielhelloworld/Sony-Camera-Control: "USB and IP/Wi-Fi camera discovery and connection" via CrSDK 2.02.00 on Windows (no body named) — [Sony-Camera-Control](https://github.com/danielhelloworld/Sony-Camera-Control)
- alphawire: TCP/IP backend exists on all three OSes but "PTPIP backend doesnt support SSL" — [alphawire](https://github.com/watsonmw/alphawire)
- Wireless to pre-2020 bodies uses the legacy HTTP JSON API (CinemaHUD on α6400 at 192.168.122.1:8080; SonnyLink on α6300; pysony/libsonyapi/rocc/timelapse-sony) — [CinemaHUD](https://github.com/shivvyas2/Sony-Alpha-A6400-Cinema-Monitor), [SonnyLink](https://github.com/XiaoQAQ10086/SonnyLink)
- Wireless image transfer from 2020+ bodies: DangerBlack found the A7R III (2017) advertises only JPEG over DLNA and never opens the PTP/IP port in Send-to-Smartphone mode — [sony-photo-transfer](https://github.com/DangerBlack/sony-photo-transfer); camera-wifi-transfer notes "some newer bodies offer only FTP or app-based transfer" and cannot use Send to Computer — [camera-wifi-transfer](https://github.com/dykomenko/camera-wifi-transfer); alpha2go and sarnau instead pull originals/RAW through the PC-Remote PTP/IP session (alpha2go: resumable ≥4 GiB; sarnau: 67 MB ARW in 4.1 s) — [alpha2go](https://github.com/Knallli/alpha2go), [sony-camera-protocol](https://github.com/sarnau/sony-camera-protocol)

### Inferences
- The "PTP 3"/SDIO-v3 generation (roughly ZV-E10/α7S III onward) is the one direct-PTP/IP projects target; each has been validated on exactly one body, so cross-model coverage is still thin and a new app should budget for per-model quirks (step-based exposure on older bodies, rejected ops on α6700 per alpha2go's matrix).
- Because every SDK-free modern-Wi-Fi project authenticates over SSH, an SSH client library (libssh2 in CrSDK, Go `x/crypto/ssh` in alpha2go) is effectively mandatory for Access-Authentication bodies.

### Gaps
- No repo documents the camera-side "Pairing" flow (Access Authentication off) for modern bodies end to end.
- Wi-Fi Direct (camera AP) PTP/IP control of 2020+ bodies from a desktop is only claimed by SonyCamViewer; the other modern projects assume an infrastructure network.

- Issue trackers were read only for alpha-fairy, sony-pm-alt and rocc; other repos' open-issue counts are listed but titles were not reviewed.

## Verdicts (one line per repo)
- RemoteCam — **fork candidate** (CrSDK, Win+Mac, Wi-Fi, MIT, closest to the goal).
- alpha2go / alpha2web — **fork candidate / study for protocol** (SDK-free PTP/IP, SSH auth, broadest documented op coverage).
- alphawire — **study for protocol** (C backends, PTP/IP without SSL, debug GUI).
- sarnau/sony-camera-protocol — **study for protocol** (BLE→Wi-Fi handoff, op codes, throughput).
- SonyCamViewer — **study** (direct PTP3 on Mac+Android, multi-cam, monitoring UI).
- remote-camera-control-rs / rocc — **architecture reference** (legacy vs. modern routing); rocc itself dead.
- RobertDamerius, jakkuh — **minimal reference**.
- CinemaHUD — **study** (macOS Swift, legacy Wi-Fi API + USB, monitoring features).
- Tether, simple-camera-remote, sony-alpha-webcam — **study** (USB-only but modern-body PTP via ImageCaptureCore/WPD; QoL ideas).
- ONAIR, Sony-Camera-Control, TetherMoon, talayolabs/sonycam, alpha-sdk-api, CrSDKPy, sony-crsdk-rust — **reference** for CrSDK integration patterns (daemon, REST, multi-cam, Windows driver notes).
- camera-wifi-transfer, spmag-sony-pm-alt-gui, ImagingEdge4Linux, ImagingEdge-Next — **study** for image-transfer UX (reconcile, atomic downloads, QR join); sony-pm-alt **dead** but historically important.
- alpharemote, freemote, furble, AlphaPro, alfa — **study** for BLE wake/remote/credential handoff.
- SonnyLink, expo-sony-camera, peiyuanix patcher — **reference** (mobile; the patcher documents Creators' App behaviour).
- pysony, libsonyapi, kz-remote-api/locana, timelapse-sony, SonyAlphaUSB, alphamote, Brqtt, blue-alpha-lib — **dead / legacy only**.
- libgphoto2 — **reference** for Sony PTP opcodes; USB-centric.
