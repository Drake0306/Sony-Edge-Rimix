# Sony official camera-connectivity apps ("Sony Edge" ecosystem) — inventory, connection methods, and mobile-vs-desktop gaps (state as of 2026-11-10)

Scope note: "Sony Edge" is the user's umbrella term. Sony's current umbrella brand is **Creators' Cloud**; the apps are Imaging Edge Desktop (Remote/Viewer/Edit), Creators' App (mobile), Imaging Edge Mobile (legacy mobile), Monitor & Control, Remote Camera Tool, Transfer & Tagging, Imaging Edge Webcam, plus the developer-facing Camera Remote Toolkit (Camera Remote SDK + Camera Remote Command). Several Sony regional support-article mirrors (sony.com / sony.ca / sony.co.uk / sony-mea / sony.co.th / sony.com.tw) returned HTTP 403 to fetches; where a fact comes only from a search-result snippet of those pages it is marked "(snippet)".

## Key Question 0: Per-app inventory — what each app does, platforms, and how it connects

### Takeaway
Sony's lineup splits cleanly: the **mobile apps (Creators' App, Monitor & Control, Transfer & Tagging) are Bluetooth-LE + Wi-Fi native** (pairing via BLE, auto-handoff to Wi-Fi, USB optional), while the **desktop apps are USB-first**: Imaging Edge Desktop Remote supports Wi-Fi (Direct and access-point) and wired LAN only on a specific subset of newer bodies, Remote Camera Tool is wired-LAN-only, and Imaging Edge Webcam is USB-only.

### Cited Findings

### Inferences
- Every Sony mobile app is designed around the camera's BLE radio as the "control plane" for discovering and waking the camera and auto-joining Wi-Fi; no Sony desktop app uses Bluetooth at all (no BLE step appears anywhere in the Imaging Edge Desktop or Remote Camera Tool documentation). That BLE bootstrap is the core thing mobile can do "wirelessly" that desktop cannot.
- The desktop apps that do support networking (Imaging Edge Desktop Remote, Remote Camera Tool, Camera Remote SDK) all rely on the camera's "Remote Shoot Function"/"PC Remote" PTP server over USB, Wi-Fi or Ethernet; the mobile apps additionally use Sony's smartphone-connection service, which is why a camera cannot be simultaneously connected to a phone and a PC.

## Key Question 1: What exactly happens when the mobile app scans the QR code on the camera (what is encoded; Bluetooth vs Wi-Fi handoff)?

### Takeaway
There are two different QR codes depending on camera generation: on Imaging Edge Mobile-era bodies the QR code encodes the camera's Wi-Fi Direct SSID ("DIRECT-xxxx") and password, which the app registers on the phone so it can join the camera's AP; on Creators' App-era bodies the QR shown on the camera is just an app-download link, and the actual connection is a Bluetooth LE pairing (6-digit confirmation) after which "the camera and Creators' App are automatically connected to Wi-Fi via the Bluetooth function."

### Cited Findings
- Imaging Edge Mobile era (a1 original firmware): "Once the QR Code has been read, this camera's SSID (DIRECT-xxxx) and password are registered to the smartphone." Steps: camera MENU → Network → Smartphone Connect → Smartphone Connection → On; Connection → shows QR; phone app "Connect with a new camera" → scan → "Connect with the camera?" → OK. "You can connect to the camera with the same operation on any Android smartphone, iPhone, or iPad." Bluetooth is not part of the QR flow; NFC is offered as an alternative; fallback is manual SSID/password. — [Sony a1 Help Guide: Connecting the camera and a smartphone using the QR Code](https://helpguide.sony.net/ilc/2040/v1/en/contents/TP1000416941.html)
- Resetting SSID/PW or editing device name invalidates previously scanned QR codes: "If you have performed [SSID/PW Reset] or [Edit Device Name]... display a new QR Code by selecting [Connection Info.] and rescan it." (snippet) — [Sony Help Guide: Connecting using the QR Code (a7S III)](https://helpguide.sony.net/ilc/2010/v1/en/contents/TP0003220942.html)
- Creators' App era: the QR on camera is for app install: "You can also install Creators' App by scanning the QR Code displayed on the screen of the camera using your smartphone." — [Sony a7 V Help Guide: Functions available with a smartphone](https://helpguide.sony.net/ilc/2540/v1/en/contents/221h_creators_app.html)
- Creators' App first-time connection: pair over Bluetooth from the app ("It is not possible to connect the camera by configuring the pairing settings on the smartphone"); location permission required; select camera model; "A six-digit number appears. Check that the same number is displayed on the camera"; then "The camera and Creators' App are automatically connected to Wi-Fi via the Bluetooth function." Later connections are automatic. VPN on the phone can block connection. — [Creators' App Help Guide: Connecting the camera (first-time connection)](https://helpguide.sony.net/di-app/ca/v1/en/contents/CA_connect_camera.html)
- Remote shooting flow: "The smartphone and camera will be connected by Wi-Fi via the Bluetooth function" and live view appears on the phone. — [Creators' App Help Guide: Remote shooting](https://helpguide.sony.net/di-app/ca/v1/en/contents/CA_remote_shooting.html)
- Camera-side pairing (ZV-1F, firmware 1.10+): MENU → Network → Cnct./PC Remote → Smartphone Connection → turn Bluetooth on → camera waits for app. Connecting without pairing: press Delete on the Smartphone Connection screen to show SSID/password, join in phone Wi-Fi settings, then in app Cameras → Setup → "connect only via Wi-Fi"; must be repeated every time. "Up to 2 devices can be connected via Bluetooth at once." Bluetooth and 2.4 GHz Wi-Fi interfere. — [Sony ZV-1F Help Guide: Pairing the camera with a smartphone](https://helpguide.sony.net/dc/2210/v1/en/contents/TP1000934579.html)
- Sony's Alpha Universe marketing describes the app guiding you "to scan a QR code or enter a password shown on your camera's screen" (snippet). — [Sony Alpha Universe: Creators' App](https://www.sony.ie/alphauniverse/creators-app)
- Sony troubleshooting: most common failure is "Bluetooth connection with the camera could not be established"; fix is to remove the camera from the phone's Bluetooth list and redo first-time pairing; iPhone shows a brief pairing request window. (snippets) — [Sony support article CCCA99011](https://www.sony.co.in/electronics/support/e-mount-body-ilce-6000-series/ilce-6000y/articles/CCCA99011)
- Forum observation of the handoff: "weird how my phone has to connect with Bluetooth to the camera" and then the phone joins the camera's own private Wi-Fi network (Gaz, Dec 2022). — [Alpha Shooters forum thread](https://alphashooters.com/community/threads/sony-a7-iv-wireless-tethering-with-imaging-edge-on-macbook-pro.4924)

### Inferences
- In the Creators' App design, BLE carries the Wi-Fi credentials/handshake (and wake-up: "Cnct. while Power OFF"), so the phone never has to see or type an SSID. Imaging Edge Desktop has no BLE path, which is why the desktop user must manually read SSID/password from the "Wi-Fi Direct Info." screen or pre-join the same router and perform pairing/access-authentication.
- The exact byte-level payload of the legacy QR (beyond SSID + password) is not documented by Sony; third-party sony-pm-alt style tooling treats it as SSID/password only.

### Gaps
- No Sony document describes the QR payload format precisely (e.g., whether it also includes a model identifier or device GUID).
- Sony does not publish what is exchanged over BLE during Creators' App pairing (credentials vs. a token); only the observable behaviour (6-digit confirmation, then automatic Wi-Fi) is documented.

## Key Question 2: Which Sony bodies support wireless PC Remote (Wi-Fi) to Imaging Edge Desktop, how is it set up, and what are the limitations?

### Takeaway
Wi-Fi PC Remote to Imaging Edge Desktop exists since Aug 2019 (a7R IV / a9 II generation onward) in two modes—Wi-Fi Direct (camera is the AP, PC joins "DIRECT-xxxx") and Wi-Fi Access Point (same router, first-time pairing on older bodies or username/password + fingerprint "Access Authentication" on newer bodies)—but a7 III-generation and older bodies, the ZV-1 compacts and most other cameras are USB-only, and Sony's own docs warn of slower live view, firewall/local-network permission issues on macOS, and the need to disconnect any smartphone first.

### Cited Findings
- Version history: Wi-Fi remote shooting added in Imaging Edge 2.0.00 (2019-08-07). — [Sony Imaging Edge Desktop support page](https://support.d-imaging.sony.co.jp/app/imagingedge/en/index.php)
- Per-model connection support (Sony's grouping): ILCE-1 group = USB + Wi-Fi Direct + Wi-Fi AP + wired LAN; ILCE-7SM3 group, ILCE-7CR/7CM2/6700, ILME-FX2, DSC-RX10M5 = USB + Wi-Fi only; ZV-E10 = USB + Wi-Fi Direct + Wi-Fi AP (pairing); ZV-1/1A/1F/1M2 = USB only; "Other cameras: USB only." Wired LAN: ILCE-1M2/1/9M3/9M2 and ILX-LR1 (needs USB-LAN adapter). "You may need to wait around 1 minute before the LAN cable is recognized." — [Imaging Edge Desktop: Connecting the camera to the computer](https://support.d-imaging.sony.co.jp/app/imagingedge/en/instruction/4_1_connection.php)
- a7 III (ILCE-7M3) help guide describes Remote only "from a computer connected to the camera with a USB cable" via MENU → Setup → [USB Connection] → [PC Remote]; no Wi-Fi option. — [Sony a7 III Help Guide: Developing RAW images/Remote shooting (Imaging Edge)](https://helpguide.sony.net/ilc/1720/v1/en/contents/TP0001667702.html)
- a7R IV (ILCE-7RM4, 2019): first generation with [PC Remote Cnct Method] = [USB] / [Wi-Fi Direct] / [Wi-Fi Access Point]; prerequisite "[Ctrl w/ Smartphone] → [Off] beforehand"; Wi-Fi Direct: read SSID/password from PC Remote Function → Wi-Fi Direct Info.; AP mode: join router via WPS Push / Access Point Set., then PC Remote Function → Pairing → complete in Imaging Edge (Remote) → OK on camera. Settings: Still Img. Save Dest. [PC Only]/[PC+Camera]/[Camera Only]; RAW+J PC Save Img [RAW & JPEG]/[JPEG Only]/[RAW Only]; PC Save Image Size [Original]/[2M]. "Pairing information is deleted when you initialize the camera." — [Sony a7R IV Help Guide: PC Remote Function](https://helpguide.sony.net/ilc/1930/v1/en/contents/TP0002728092.html)
- a7C (ILCE-7C, 2020): same three methods and same pairing procedure; "strongly recommend" WPA2 AP; "If unauthorized access is detected, the camera may stop accepting communication." — [Sony a7C Help Guide: PC Remote Function](https://helpguide.sony.net/ilc/2020/v1/en/contents/TP1000156203.html)
- a7S III (ILCE-7SM3): MENU → Network → [Transfer/Remote] → [PC Remote Function]; [USB]/[Wi-Fi Direct]/[Wi-Fi Access Point]; pairing for AP mode. (snippet) — [Sony a7S III Help Guide: PC Remote Function](https://helpguide.sony.net/ilc/2010/v1/en/contents/TP0003228392.html)
- a7R V (ILCE-7RM5): "Remote Shoot Function" terminology; AP mode: MENU → Network → Wi-Fi → Wi-Fi Connect → On; Cnct./Remote Sht. → Remote Shoot Function → Remote Shooting → On; "Access Authen. Info" shows username, password and fingerprint (also under Network Option); enter in Imaging Edge Desktop (Remote). Pairing only if Access Authen. is Off. Wi-Fi Direct: Remote Shoot Function → Wi-Fi Direct Info. USB: select "Remote Shooting" on camera screen. "When the camera and a smartphone are connected, you cannot control the camera from a computer." "If you set [Access Authen.] to [Off], communication will be performed without authentication or encryption via SSH connection" [sic — Sony's text]. ## Key Question 5: Ports/protocols mentioned in Sony guides or FAQs (PTP/IP 15740, FTP, SSH, etc.)

### Takeaway
Sony never publishes port numbers for consumer apps; its only protocol statements are that Camera Remote Command is "Sony's proprietary extension of the ISO standard PTP" with PTP-IP added in Oct 2024, that FTP (camera as client) is the transfer protocol used by Transfer & Tagging, and that AP-mode remote shooting without Access Authentication runs "without authentication or encryption"; the well-known PTP/IP port 15740 comes from the ISO standard and community reverse engineering (gphoto2, sony-pm-alt, ptp-ip), not from Sony.

### Cited Findings
- "Sony's proprietary extension of the ISO standard PTP (Picture Transfer Protocol)"; "control over IP connection (PTP-IP)" added 2024-10-16; interfaces USB / Wired LAN / Wireless LAN. — [Sony Camera Remote Command page](https://support.d-imaging.sony.co.jp/app/cameraremotecommand/en/index.html)

- Imaging Edge FAQ mentions only "firewall" (add Imaging Edge Remote as exception) and macOS "Local Network" permission; no ports listed. — [Imaging Edge Desktop FAQ](https://support.d-imaging.sony.co.jp/app/imagingedge/en/faqs/)
- PTP/IP default port: "Default port is 15740 (same as the ISO standard number for PTP)". — [gPhoto PTP/IP documentation](https://gphoto.sourceforge.io/doc/ptpip.php)
- Community: Sony camera "starts up a PTP/IP server on port 15740 when it boots" (sony-pm-alt, wireless transfer without PlayMemories). — [sony-pm-alt on GitHub](https://github.com/falk0069/sony-pm-alt); [ptp-ip Go implementation](https://github.com/malc0mn/ptp-ip)

- Wake On LAN supported by Remote Camera Tool 4.1/5.1 for ILCE-1 / ILCE-9M3 (snippet). — [Sony support article DIRCT01000](https://www.sony.ca/en/electronics/support/e-mount-body-ilce-1-series/ilce-1/articles/DIRCT01000)
- Sony FTP help guide exists as a separate "FTP Help Guide" with frequency-band settings. — [Sony FTP Help Guide: Frequency Band](https://helpguide.sony.net/di/ftp/v1/en/contents/TP0002432598.html)
- Old Camera Remote API (JSON-RPC over HTTP via SSDP discovery, "Smart Remote Control" era) was closed: Feb 2020 press release said the SDK succeeds the API and "supported Cameras by current Camera Remote API are not included in compatible cameras' line-up for Camera Remote SDK" (snippet); docs archived; API still functions on its supported devices per Sony's note (snippet). — [Sony press release 2020-02-12](https://sony.mediaroom.com/2020-02-12-Sony-Electronics-Announces-New-Camera-Software-Development-Kit-for-Third-party-Developers-and-Integrators); [StackOverflow: Sony Camera Remote API archived](https://kiwix.lema.org/stackoverflow.com_en_all_2023-11/questions/52010256/sony-camera-remote-api-archived)

### Inferences
- Imaging Edge Desktop Remote over Wi-Fi almost certainly speaks the same Sony-extended PTP/IP that Camera Remote Command documents (same "Remote Shoot Function" server on the camera; same access-authentication credentials), i.e., TCP 15740 for command/event channels; this is an inference from the protocol statements and community captures, not a Sony statement.
- Sony's "SSH" wording in the Access Authen. note most likely refers to its SSH-style fingerprint-verified encrypted channel wrapping PTP/IP rather than a literal shell login; Sony does not elaborate.

### Gaps
- No Sony document lists port numbers for Creators' App, Imaging Edge Desktop, Monitor & Control or Remote Camera Tool discovery/control.
- The exact encryption scheme behind "Access Authentication" (fingerprint + user/password) is undocumented publicly.
